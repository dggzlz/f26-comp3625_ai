Question 2:
How confident are you that your model has not overfit the historical data? Why?

We are confident the model has not overfit, since it scores almost the same on the training set as on the test set
(accuracy 47.70% vs 47.96%, sensitivity 81.76% vs 82.10%, specificity 30.87% vs 30.57%, printed at lines 213-231
in model_dev.py). An overfit model would score much better on the data it was trained on.

Moreover, guessing someone is risky when they are safe (a false positive) just means the company lose out on a small premium, 
guessing someone is safe when they are risky (a false negative) means the company have to pay a huge $100,000 claim. 
To maximize the $100M budget, the Simulated Annealing algorithm put the model to a high sensitivity (~82%), 
identifying almost everyone who will make a claim and aggressively rejecting anyone with a chance of risk. 
This drops the specificity (false positives), but maximizes the absolute financial profit.


Question 3:
In this assignment scenario, which party is acting according to the principle of maximum expected utililty? The customer? Your program? Both?

In this case, both are acting in accordance to the principle of maximum expected utility.
The customer is evaluating and comparing whether it is worth going uninsured vs going insured. [line 74: utility.py].
On the other hand, the program only cares for profitability. The program is comparing the benefits of insuring a set of
customers vs. how much it would cost them to insure said set of customers [line 77: utility.py]. Maximizing expected
profit is the same as maximizing expected utility when every dollar is worth the same, so the program follows the
principle too, it just doesn't fear risk the way the customer does.


Additional Notes:

Initially we decided to go for KNN model instead of Logistic Regression. For KNN we decided to use a search
algorithm that scales each feature depending on the importance of it, e.g. age might be not as relevant as income, so the algorithm would
set a factor for each, making age less important. Once built, we ran into the problem where the algorithm was taking too long,
just in the initial base run. The main reason for this is that KNN is sensitive to dimensions, i.e. the bigger the list of features (dimensions) 
the longer it would take for the model to run. We decided to add a feature selection algorithm, but realized that the main problem was the first 
run with the initial 21 features. This was the major bottleneck. Furthermore, we tested sklearn's KNN and ran the first base model in ~1 second. 
Sklearn's model uses specialized, more complex data structures that are out of the scope of the class, for this reason we decided to pivot to 
Logistic Regression, which works pretty well, since Logistic Regression does not get affected by the dimensionality problem.
